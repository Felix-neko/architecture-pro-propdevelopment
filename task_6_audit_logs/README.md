# Задание 6. Аудит активности пользователей и обнаружение инцидентов

## Как запускался

Я честно пытался запустить `minikubе` с той политикой аудита, которую нам давали в задании, ничего в ней не меняя (см. [audit-policy-raw.yaml](audit-policy-raw.yaml) и [setup_minikube_raw_policy.sh](setup_minikube_raw_policy.sh)) -- однако злоехидный `minikube` с нею упорно не желал заводиться (см. [running_minikube_with_raw_policy.log](running_minikube_with_raw_policy.log))

Поэтому я достал Claude -- и нагенерировал себе новых политик аудита, тестируя их следующим образом.

```bash
minikube delete
bash setup_minikube.sh
kubectl logs -f kube-apiserver-minikube -n  kube-system | grep audit.k8s.io/v1  # для просмотра audit-логов
```
Хинт: тут можно сделать clear terminal, чтобы смотреть только новые логи аудита, связанные с "попыткой атаки".

И запускаем скрипт-имитатор-атаки:
```bash
bash simulate_incident.sh
```
И сохраняем свежие логи аудита, когда скрипт отработает.

### Попытка 1. Логируем вообще всё
В первый раз я попросил Claude выставить [максимально подробный аудит](audit-policy-backup.yaml), чтобы ничего не упустить.

Объём логов оказался великоват для чтения вручную (3.6 МБайт за примерно 3-4 секунды), а вычленять из них главное с помощью `jq` я ещё не умел, потому что не знал, что искать.
Поэтому я снова достал Claude Sonnet 4 и скормил ему эти логи, велев разобраться, что там происходит, и дать комментарии.

> Опиши, что значит каждое событие в логах.

Результат оказался такой себе: в этих логах Claude не нашёл ничего критического (см. его [комментарии](logs_for_analyze_from_new_minikube_commented.md)):

### Попытка 3. Сойдёт за золотую середину?

В итоге, с помощью Claude, я пришёл к той политике, которая сейчас стоит в [audit-policy.yaml](audit-policy.yaml). Там добавилось:
- Логирование exec-операций (pods/exec, pods/attach, pods/portforward)
- Расширенное покрытие RBAC (убрано ограничение по namespaces)
- Отслеживание impersonation (операции с --as)
- Мониторинг проверок прав (can-i)

[Новые логи](logs_for_analyze_3.log) наконец-то стали отображать создание RoleBinding (если надо, вот [Claude-комментарии по всем их событиям](logs_for_analyze_3_comments.md), там всё правильно находится).

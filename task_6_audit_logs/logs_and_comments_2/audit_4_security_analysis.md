## 2. ЧТЕНИЕ И УДАЛЕНИЕ ПОЛИТИК БЕЗОПАСНОСТИ

### Поиск в логе kubectl exec команд
К сожалению, в представленном audit логе не обнаружены события kubectl exec для чтения и удаления файла `/host/etc/ssl/certs/audit-policy.yaml`. Это может означать:
1. События exec не логируются на уровне Metadata
2. Команды выполнялись в другом временном окне
3. Политика аудита не настроена для логирования exec команд

**Ожидаемые вредоносные действия (из скрипта):**
```bash
kubectl exec -it privileged-pod -- cat /host/etc/ssl/certs/audit-policy.yaml
kubectl exec -it privileged-pod -- rm /host/etc/ssl/certs/audit-policy.yaml
```

**Уровень угрозы:** КРИТИЧЕСКИЙ
**Комментарий:** Удаление политики аудита - это попытка скрыть следы вредоносной активности и отключить мониторинг безопасности.

1. **Отсутствие Pod Security Standards** - разрешено создание привилегированных подов
2. **Слабые RBAC политики** - возможность создания cluster-admin привязок
3. **Недостаточное логирование** - не все вредоносные действия попали в audit лог

### Рекомендации:
1. Внедрить Pod Security Standards для блокировки привилегированных подов
2. Ограничить возможность создания RBAC привязок с высокими привилегиями
3. Настроить более детальное аудит-логирование (уровень Request/Response)
4. Внедрить мониторинг аномальной активности в реальном времени
5. Регулярно проверять ServiceAccount и их привилегии
